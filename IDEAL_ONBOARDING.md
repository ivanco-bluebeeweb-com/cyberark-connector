# CyberArk Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: security
engineer или PAM-администратор, впервые открывающий приложение.

## 1. Credential type
PVWA base URL (`https://{pvwa-host}/PasswordVault`) + username/password (CyberArk
или RADIUS аутентификация).

## 2. Идеальный флоу (без ограничений SDK)
1. **Явный выбор метода аутентификации** — переключатель "CyberArk" / "RADIUS"
   перед формой, так как это два разных эндпоинта логона, а не один универсальный.
2. **Проверка перед сохранением** — реальный `POST /auth/Cyberark/Logon` (или
   `/auth/RADIUS/Logon`) и один тестовый вызов `GET /Safes?limit=1`, чтобы сразу
   подтвердить и хост, и креды, и права аккаунта на чтение Safes.
3. **После успеха — vault health snapshot** — число Safes, число accounts,
   accounts просроченные по ротации (если платформа отдаёт `lastSuccessChange`),
   чтобы пользователь сразу увидел, что подключение реально работает.
4. **Явное предупреждение о времени жизни сессии** — токен CyberArk по умолчанию
   истекает через ~20 минут простоя; коннектор должен молча переавторизовываться
   на 401 без падения в чат пользователя ошибкой "unauthorized" на ровном месте.
5. **Ошибки — по конкретному коду CyberArk, не generic 401/403** — например,
   `ITATS982E` (invalid credentials) или `PASWS004E` (retrieval requires
   confirmation) должны переводиться в понятную формулировку с конкретным
   следующим шагом (например "запросите доступ через create_access_request"),
   а не отображаться как сырой код ошибки.
6. **Двухшаговое подтверждение перед get_account_password и
   change_account_password** — явный текст "вы получите/смените реальный
   привилегированный пароль в проде", т.к. это самое чувствительное действие во
   всём приложении.
7. **Явная причина (reason/ticket-id) как обязательное поле при retrieval**,
   если Safe настроен на dual control — CyberArk сам требует это поле для
   аудита, коннектор должен просить его сразу, а не после отказа API.
8. **Multi-vault** — переключатель между несколькими подключёнными PVWA (прод +
   DR), т.к. крупные организации почти всегда держат больше одного vault.
